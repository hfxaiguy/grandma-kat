# Taste
- Refers to time loosely by relative day names ("tuesday and wednesday this week", then "maybe it was tuesday and monday") and expects the agent to resolve them into concrete dates itself and run with the best guess — offering the other plausible interpretation — rather than stopping to ask which dates are meant. Confidence: 0.5
- Pushes back on thin placeholder text meant for a model (or human) to act on — expects instructions/prompts to be complete and self-contained: the full surface of options, hard rules, common pitfalls, the input/output contract, and the available inventory, not a sketch. Confidence: 0.65
- When a prompt/guide teaches an idiom, expects it to feature the library's dedicated element as *the* way to do it and to name the hand-rolled alternatives as explicit anti-patterns (e.g. "use `From('name', memory(...))`; do not hand-roll it with extra `Memory()` steps or a `Branch` wrapper"). Confidence: 0.6
- Favors reuse/composition of already-defined components over re-implementation — existing artifacts should be importable by name and fed the inputs they expect, and that capability should be taught to the authoring model, not just left implicit. Confidence: 0.6
- Insists that an autonomous/iterative loop give the actor real access to observe and test — e.g. authoring/repair rounds must have tool access to real data (`sql_query`) and the ability to test-run a candidate, rather than iterating blind on guesswork; treat observability/testability as a minimum requirement, not a nice-to-have. Confidence: 0.6
- Weighs risk before promoting an experimental/unproven approach into core infrastructure — asks outright "is that a bad idea?" and favors a staged, safer path (e.g. a read-only dev-time factory or a gated fallback) over making it the main path by default. Confidence: 0.5
- For data-processing pipelines, prefers tool/query results to stay as live structured objects in memory and be transformed with plain language constructs (map/filter) rather than being serialized to JSON or routed back through a model round-trip; treats avoiding unnecessary serialization as a deliberate design goal — but it is tradeable, not absolute: readily accepts a hard JSON/process boundary when it buys isolation or robustness (e.g. a tree running in its own process "without sharing memory"). Confidence: 0.5
- Acknowledging a solution is good is not acceptance if it requires hard-coding — explicitly rejects hand-authored/fixed structures in favor of dynamic or generated ones where the structure and values are produced at runtime rather than baked into source. Confidence: 0.55
- Weighs security situationally rather than absolutely, and will explicitly waive it ("i don't care about security considerations") when hardening would constrain the design/behavior being built — security is a per-task tradeoff the user will trade away for the exact behavior they want, not a fixed requirement. Confidence: 0.5
- Prioritizes closing security gaps in code that runs model/untrusted-generated input — actively looks for ways to avoid executing that input as code (eval / `new Function` / `vm`) and leans toward having it emit declarative data interpreted by trusted, human-written code, accepting a smaller closed vocabulary and reduced expressiveness as the price. Confidence: 0.55
- Switches models mid-session and signals it tersely ("just switched model, continue"), expecting the new model to resume the in-progress work seamlessly — no recap, no re-asking, no re-litigating decisions already made; just pick up where the previous model left off. Confidence: 0.4
- Readily relaxes his own earlier hard design requirements once the trade-offs are laid out — e.g. dropped the "must run as if it was an imported branch at build time" (shared memory, structural execution) requirement in favor of the tree running in its own process without shared memory — prioritizing robustness/simplicity over execution fidelity rather than defending the original semantics. Confidence: 0.5
- When revising a constraint mid-design ("actually, it's probably fine for X... does that change much?"), expects a focused delta analysis — which previously-listed difficulties disappear, what new work appears, and the cheapest shape that captures most of the win — not a from-scratch re-answer. Confidence: 0.5
- Writes experimental/scratch code as real files in a scratch directory (e.g. `patterns/scratch/<name>/...`) and executes the file, rather than inline/eval'd snippets — and follows the workspace `.mjs` + `.md` artifact convention with the `.md` spec written first, before the implementation. Confidence: 0.7
- Prefers re-instantiating a child process's tools/dependencies locally over IPC/proxy plumbing back to the parent, and wants zero data passed across the process boundary ("nothing needs to be passed between child and parent process") — full isolation, no cross-process contract. Confidence: 0.65
- Before implementation, asks "anything else left?" — expects any remaining open decisions/defaults to be enumerated for confirmation before building, rather than the assistant silently picking them. Confidence: 0.4
- Leans toward baking authoring/usage guidance directly into the prompt itself so the model can't miss it — questions whether separate reference files are even needed ("should be baked into the prompt, no? or better to give it reference files?"). Confidence: 0.45
- Wants dynamically-named, per-instance tools/registers keyed by the artifact's own name (e.g. `Register('scratch_[name]')`) so each generated item is addressable and re-runnable by its own name, rather than one fixed generic entry point. Confidence: 0.5
- Wants generated/saved modules to stay inert pattern modules (a plain `const pattern = …; export default pattern;`) with no self-running footer or top-level side effects — "BOB should be the one to run them", via a single shared runner that dynamic-imports the file, wires the runtime, and executes it — rather than the artifact executing itself on import/run. Confidence: 0.6
- Insists that transforming model-written output into a saved file be fully deterministic — a pure template composition (fixed prelude + body written verbatim + fixed trailer), no parsing of model output, no regexes, no inference — so the same input always yields the same file. Confidence: 0.65
- Expects a promotion/graduation path from experimental/scratch artifacts to durable, reusable, first-class ones — anything built in a scratch area should have a way to be "saved for future use" (promoted to the canonical location, importable by name, kept alongside its spec) rather than stranded as a throwaway experiment. Confidence: 0.5
